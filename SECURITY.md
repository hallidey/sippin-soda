# Security

This project is pre-release and is intended for controlled development traffic. The proxy binds to IPv4 loopback only after explicit Start. It installs no CA and never changes system proxy settings. CONNECT forwards an opaque TCP stream, typically TLS: certificate validation remains between the client and upstream. CONNECT can carry other TCP protocols too; it does not enforce TLS or classify destinations. Direct HTTP Upgrade remains unsupported. TLS interception is not implemented.

Metadata captures redact complete query strings and retain only allowlisted header values. URL paths remain visible and can contain secrets; do not treat this as complete sensitive-data redaction. Optional body recording is disabled by default. When enabled it stores unredacted, unencrypted decoded response bytes in local temporary files; header redaction does not protect response body contents. JSON request bodies up to 1 MiB are redacted recursively by a built-in sensitive-key policy before a separate inspection copy is written to disk. The original request is forwarded unchanged and never written by request inspection. Non-JSON, invalid and oversized request bodies are not recorded. CONNECT payloads are never recorded. See [HTTP proxy limits](docs/HTTP_PROXY.md).

Temporary body files use tempfile's private file creation and independent, securely reopened handles. IPC accepts capture IDs and bounded byte ranges, never paths. Clear, eviction and normal app exit remove owned body files; Stop retains captures for inspection. A crash or forced process termination can leave named temporary files behind, and deletion is not secure erasure. Do not enable raw recording for traffic whose contents must not reach disk. Full sensitive-data redaction and encrypted session storage remain future work.

The optional JSON layout is another unredacted temporary file, charged to the same budget and removed with its capture. Search and layout run locally with two concurrent analysis jobs at most. Queries are literal UTF-8 with a 4096-byte cap; each search scan reads at most 4 MiB. JSON layout enforces UTF-8, syntax and 128-level nesting checks without loading a complete document tree. Neither feature changes the forwarded body or substitutes for redaction.

Do not include credentials, private keys or unredacted traffic in public issues. Report suspected vulnerabilities through GitHub's private vulnerability reporting when enabled; otherwise contact the maintainer privately before disclosing sensitive details. A dedicated security contact and release support policy will be established before distribution.
